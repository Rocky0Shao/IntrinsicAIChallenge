## Daily Update: Simplified CheatCode Teleop for Clean ACT Training Data

Today's focus was stripping the cheatcode teleop down to a clean, no-recovery state machine (`INIT → APPROACH → ALIGN → INSERT → DONE`) by removing all SEARCH/wiggle and RECOVERY/retreat phases. Since ACT learns by imitation, any retry or search behavior in the training data would teach the model to fail first and then recover — exactly what we don't want. The key changes include: enabling wrench feedback compliance gains (`[0.5, 0.5, 0.5, 0, 0, 0]`) in the controller for automatic lateral correction during insertion, switching to an XY-only integrator that tracks plug-tip-to-port error (matching the official CheatCode architecture), tightening alignment tolerances (0.5mm XY, 0.03rad angular, 2s minimum dwell), and using constant-speed descent at 12mm/s with only a simple safety hold at 19.5N instead of force-proportional rampdown. The integrator is now preserved across the ALIGN→INSERT transition so the built-up XY correction carries through, and angular gain is reduced to 25% during insertion to prevent binding torques.

Next up, I'm planning to implement two separate cheatcode teleop configurations — one tuned for SFP connectors (rectangular, tight chamfer, trials 1 & 2) and one for SC connectors (round, spring-loaded latch, trial 3). The SC port needs different tuning: slower insertion speed to handle the latch engagement, longer alignment dwell for the round geometry, and a higher force threshold since the spring latch creates natural force spikes. Once both configs are reliably hitting 100% first-try insertions in simulation, I'll start collecting 50+ demonstration episodes per trial for ACT model training.
