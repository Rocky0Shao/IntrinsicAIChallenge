# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This repository is for the **AI for Industry Challenge** - an open competition to develop AI models that autonomously insert fiber optic cables into ports using a UR5e robot arm. The current development focus is on training an **ACT (Action Chunking with Transformers)** imitation learning model using demonstration data generated by a velocity-based cheatcode teleoperator.

**Key Constraint for ACT Training**: Training data must show clean, successful first-try insertions with NO wiggle, search, or recovery behaviors. ACT learns via imitation - if training data includes retry logic, the model will learn to fail first then recover, which is undesirable.

## Repository Context

This is a fork of the official [intrinsic-dev/aic](https://github.com/intrinsic-dev/aic) toolkit with custom modifications for LeRobot integration and ACT model training. Development happens in Rocky's custom packages under `mystuff/` and `aic_utils/lerobot_robot_aic/`.

**Competition Details**:
- Prize Pool: $180,000 ($100k 1st place)
- Task: Insert SFP and SC fiber optic connectors into ports on a task board
- 3 Qualification Trials: Trial 1 (SFP→NIC0), Trial 2 (SFP→NIC1), Trial 3 (SC→SC Port 1)
- Scoring: Model validity (0-1) + Performance (up to 24) + Task success (up to 75) = 100 pts/trial
- Major penalties: Force >20N sustained >1s (-12pts), Off-limit contacts (-24pts)

## Critical Architecture Differences

### Velocity-Based vs Position-Based Control

**Official CheatCode** (`aic_example_policies/ros/CheatCode.py`):
- Sends absolute **position targets** using `TrajectoryGenerationMode.MODE_POSITION`
- Controller at 500Hz drives robot toward exact pose
- Wrench feedback gains: `[0.5, 0.5, 0.5, 0.0, 0.0, 0.0]` (passive lateral compliance)

**Custom Teleop CheatCode** (`aic_utils/lerobot_robot_aic/lerobot_robot_aic/aic_teleop.py`):
- Sends **velocity commands** using `TrajectoryGenerationMode.MODE_VELOCITY`
- Required by LeRobot framework for ACT training data collection
- Commands at ~10-30Hz, controller interpolates to ~500Hz
- Wrench feedback gains: **MUST be `[0.5, 0.5, 0.5, 0.0, 0.0, 0.0]`** (modified from original `[0, 0, 0, 0, 0, 0]`)
  - Location: `aic_robot_aic_controller.py:412`
  - Provides automatic lateral compliance during insertion
  - When plug contacts port wall (10N lateral), controller auto-deflects with 5N corrective force
  - **This is the single most critical feature for reliable insertion**

### State Machine Architecture

**State Flow**: `INIT → APPROACH → ALIGN → INSERT → DONE`

**INIT**: Wait for ground-truth TF frames to become available
- Port frame: `task_board/{module_name}/{port_name}_link`
- Plug tip frame: `{cable_name}/{plug_name}_link`
- Gripper: `gripper/tcp`

**APPROACH**: Descend from current position to ~20cm above port
- `z_offset` starts at `approach_height=0.20`
- PI controller drives toward target position
- Integrator is **zeroed** during this phase to prevent XY overshoot
- Transitions when close enough (dist < 0.01m) and elapsed > 1.5s

**ALIGN**: Fine alignment at hover height above port
- `z_offset = hover_height = 0.03` (3cm above port)
- XY alignment tolerance: `align_xy_tolerance = 0.0005` (0.5mm)
- Angular alignment tolerance: `align_angular_tolerance = 0.03` (1.7°)
- Minimum dwell: `align_min_dwell = 2.0s` (ensures stability before insertion)
- Timeout: `align_timeout = 8.0s`
- **Integrator is preserved** across ALIGN→INSERT transition to carry XY correction

**INSERT**: Constant-speed descent until insertion depth reached
- Descends from `z_offset=0.03` to `insertion_depth=-0.015` (1.5cm below port surface)
- Constant speed: `insertion_base_speed = 0.012 m/s` (12mm/s, ~40% faster than original)
- **No force rampdown** - constant speed push-through (matches original CheatCode strategy)
- Safety hold only: if force > 19.5N sustained for >0.8s, hold at zero velocity
- Velocity limit during INSERT: `max_linear_vel * 0.5 = 0.02 m/s`
- Angular gain reduced: `kp_angular * 0.25 = 0.5` (prevents binding torques)

**DONE**: Insertion complete, dwell for confirmation
- Triggered when plug TF reaches `insertion_depth + 0.005` margin
- Dwells for `insertion_dwell = 2.0s` before declaring success
- All velocities zeroed

### PI Velocity Controller Architecture

**Critical Implementation Details**:

1. **XY-only integrator with plug-tip tracking** (lines 730-765 in aic_teleop.py):
   ```python
   # Proportional term: full gripper error (3D)
   lin_err = target_pos - gripper_pos

   # Integral term: plug-tip-to-port XY error ONLY
   plug_xy_error = port_pos[:2] - plug_pos[:2]
   self._lin_err_integrator[:2] += plug_xy_error  # XY only
   self._lin_err_integrator[2] = 0.0  # Never integrate Z

   # Combined velocity command
   v_linear_world = cfg.kp_linear * lin_err + np.array([
       cfg.ki_linear * self._lin_err_integrator[0],
       cfg.ki_linear * self._lin_err_integrator[1],
       0.0  # No integral term for Z
   ])
   ```

2. **Why XY-only?**
   - Z descent is managed by explicit `z_offset` ramp, not by PI controller
   - Integrating Z error during ALIGN phase (while holding at hover_height) causes windup
   - Windup creates velocity spikes when INSERT begins → premature contact

3. **Why plug-tip tracking?**
   - Cable droop/flex means gripper position ≠ plug-tip position
   - Systematic offset between gripper TCP and plug tip varies with pose
   - Tracking `port_pos - plug_pos` directly compensates for cable physics
   - Matches original CheatCode's integrator architecture (lines 139-164 in CheatCode.py)

4. **Gains**:
   - `kp_linear = 1.0`, `ki_linear = 0.2`
   - `max_integrator_windup = 0.05` (clips to ±5cm offset correction)
   - `kp_angular = 2.0` (reduced to 0.5 during INSERT)

5. **World-frame to TCP-frame transformation**:
   ```python
   v_linear_tcp = r_current.inv().apply(v_linear_world)
   v_angular_tcp = r_current.inv().apply(v_angular_world)
   ```
   Controller expects velocities in TCP frame, so world-frame commands are rotated.

## Ground Truth TF Frames

**CRITICAL**: Ground truth transforms are ONLY available during training/recording, NOT during competition evaluation. ACT model must learn to insert without ground truth.

**Available frames during training**:
- `task_board/{module_name}/{port_name}_link` - Port pose in base_link
- `{cable_name}/{plug_name}_link` - Plug tip pose in base_link
- `gripper/tcp` - Gripper tool center point
- `base_link` - Robot base (world frame)

**TF lookup**:
```python
self._tf_buffer.lookup_transform("base_link", port_frame, Time())
```

## Force/Torque Handling

**Sensor**: Wrist-mounted F/T sensor, published on `/observations` topic
- Raw readings: `msg.wrist_wrench.wrench.force`
- Tare offset: `msg.controller_state.fts_tare_offset.wrench.force`
- Tared force: `raw_force - tare_offset`

**Force magnitude**: Rotation-invariant norm of tared force vector
```python
tared_force = raw_force_vec - self._tare_offset
force_mag = float(np.linalg.norm(tared_force))
```

**Normal insertion forces**:
- SFP: 10-13N sliding friction on metal rails
- SC: 15-25N (includes spring latch engagement)

**Safety threshold**: 19.5N sustained for >0.8s triggers zero-velocity hold
- Does NOT retreat or wiggle (would create bad ACT training data)
- Waits for force to drop naturally

**Scoring penalty**: Force >20N sustained >1s triggers -12pt penalty
- Original CheatCode scores 60pts with NO force penalties
- With wrench feedback compliance, should stay under 15N

## Parameter Tuning Guide

### If Alignment is Unstable
- Increase `align_min_dwell: 2.0 → 3.0` or `4.0` (more settling time)
- Tighten tolerances: `align_xy_tolerance: 0.0005 → 0.0003`
- Tighten angular: `align_angular_tolerance: 0.03 → 0.02`

### If Descent is Too Slow
- Increase `insertion_base_speed: 0.012 → 0.015`
- But stay under 0.02 to avoid jerk/smoothness penalties

### If Descent is Too Fast/Aggressive
- Decrease `insertion_base_speed: 0.012 → 0.008`
- Increase `align_min_dwell` to ensure better pre-insertion alignment

### If Binding/Jamming During Insertion
- Verify wrench feedback gains are set to `[0.5, 0.5, 0.5, 0, 0, 0]`
- Check ALIGN logs - was alignment good before INSERT? (xy_err < 0.001m)
- Reduce angular gain further during INSERT: `kp_angular * 0.25 → kp_angular * 0.1`
- Slow down: reduce `insertion_base_speed`

### Trial 3 (SC) Specific Tuning
If SC connector struggles after SFP works well:
- Slower insertion: `insertion_base_speed: 0.012 → 0.010` (handle latch engagement)
- Longer dwell: `align_min_dwell: 2.0 → 3.0` (more settling for round geometry)
- Higher force threshold: `force_hold_threshold: 19.5 → 22.0` (latch creates spike)
- Tighter angular alignment: `align_angular_tolerance: 0.03 → 0.02` (round connector less forgiving)

Implement trial-specific overrides via command-line args or config files.

## Common Failure Modes and Debugging

### "Plug hovers above port, doesn't descend"
**Symptoms**: Enters INSERT phase but z_offset barely changes
**Causes**:
1. Force rampdown activating prematurely (check force readings)
2. Z integrator windup fighting descent (should be zeroed now)
3. Tare not applied (check `_has_tare` and `_tare_offset` values)

**Debug**:
- Check `[INSERT]` logs for `descent_rate` - should be ~0.012 m/s
- Check `force` - should be <5N before contact, 10-15N during insertion
- Check `z_offset` - should decrease from 0.03 → -0.015 over ~4 seconds

### "Binding/jamming during insertion, high forces"
**Symptoms**: Force spikes >15N, descent stalls, safety hold activates
**Causes**:
1. Missing wrench feedback compliance (check controller line 412)
2. Poor alignment before INSERT (check ALIGN logs)
3. Angular controller fighting port geometry

**Debug**:
- Check `[ALIGN]` logs before INSERT - `plug_xy_err` should be <0.001m
- Check `angular_error` - should be <0.03 rad
- Verify wrench feedback gains in controller output/logs

### "Alignment never converges, ALIGN timeout"
**Symptoms**: ALIGN phase times out after 8s, proceeds with poor alignment
**Causes**:
1. Integrator not converging (check integrator values in logs)
2. Cable dynamics causing oscillation
3. Tolerances too tight for cable flex

**Debug**:
- Watch `[ALIGN]` logs - are errors decreasing?
- Check `integrator=[x, y]` values - should stabilize around ±0.01
- If oscillating, reduce `kp_linear` or increase damping

### "Insertion completes but gets low score"
**Symptoms**: Plug inserts but trajectory is jerky or force penalty triggered
**Causes**:
1. High jerk (rapid acceleration changes) → smoothness penalty
2. Force >20N sustained >1s → -12pt penalty
3. Long task duration → time penalty

**Debug**:
- Review force logs - any sustained >20N periods?
- Check task duration - should be 15-30s for good score
- Review velocity commands - are they smooth or spiking?

## Important Constraints and Rules

### ACT Training Data Quality
- **NO wiggle/search behaviors** - creates bad training data
- **NO recovery/retry logic** - model would learn to fail first
- **Only clean, successful first-try insertions**
- **Smooth, consistent trajectories** - high jerk hurts learned policy

### Controller Constraints
- Commands accepted at 10-30 Hz, interpolated to 500 Hz
- Velocity mode: outputs incremental velocities, not absolute poses
- Controller resets tracking error if significant error persists
- Tare NOT available during competition evaluation (only during training)

### Scoring Penalties to Avoid
- Force >20N sustained >1s: -12 pts
- Off-limit contact (task board, enclosure): -24 pts
- Wrong port insertion: -12 pts
- High jerk: reduced smoothness score (0-6 pts)
- Long duration: reduced time score (0-12 pts)

### Physical Constraints
- SFP connectors: Rectangular, ~0.5mm chamfer, prone to "coffin corner" binding
- SC connectors: Round, spring-loaded latch, more forgiving angularly
- Cable flexibility: Plug tip can offset from gripper TCP by 1-5mm
- Insertion depth: -0.015m below port surface for full seating

## Advanced Topics

### Quaternion Math for Orientation Alignment
The cheatcode computes target gripper orientation to align plug with port:
```python
# Plug-to-port rotation
q_plug_inv = (-q_plug[0], q_plug[1], q_plug[2], q_plug[3])
q_diff = quaternion_multiply(q_port, q_plug_inv)

# Apply to current gripper orientation
q_gripper_target = quaternion_multiply(q_diff, q_gripper)
```

This ensures plug orientation matches port orientation regardless of cable routing.

### Target Position Computation
Gripper target position maintains plug-tip at desired offset above port:
```python
plug_offset = gripper_pos - plug_pos  # Current gripper-to-plug offset
target_pos = np.array([
    port_pos[0] + plug_offset[0],
    port_pos[1] + plug_offset[1],
    port_pos[2] + plug_offset[2] + z_offset  # z_offset descends during INSERT
])
```

This moves gripper such that plug tip ends up at `port_pos + (0, 0, z_offset)`.

### Rotation Error for Angular Controller
```python
r_current = R.from_quat([q_gripper[1], q_gripper[2], q_gripper[3], q_gripper[0]])
r_target = R.from_quat([q_gripper_target[1], ...])
r_error = r_target * r_current.inv()
angular_error_vec = r_error.as_rotvec()  # Axis-angle representation
```

The rotation error vector is fed to proportional controller to generate angular velocities.

### Universal DONE Detection
Insertion completion is detected by monitoring actual plug TF position:
```python
actual_plug_port_z = plug_pos[2] - port_pos[2]
if actual_plug_port_z <= cfg.insertion_depth + 0.005:
    # Dwell for cfg.insertion_dwell seconds, then DONE
```

This works even if state machine is in unexpected phase (robustness feature).
